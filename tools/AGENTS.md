# Tools

## Purpose
Generate, validate and install the original car mod.

## Ownership
Python build/install tools, native Java import probes and disposable Lua runtime audits.

- Installer preserves existing unrelated mods and saves.
- `validate_mod.py` performs standard-library static checks on the Build 42 package, manifest, asset references, PNG dimensions and optional native template/callback references. It never claims driving or animation verification.
- Validator interaction-area checks use the native 0.15 m navigation padding and 30% inward area-target offset, requiring 25 mm remaining clearance. They catch unreachable seat/service targets before runtime and are scoped to this vehicle's metre-based, unit-scale chassis.
- The conservative physics-origin check requires `wheelRadius - wheelOffsetY - modelOffsetY - suspensionRestLength >= 0.05 m`. Native wheel connections add the model offset and suspension rest length. This catches a root at or below ground before load compression; actual settled height and pathfinding remain runtime gates.
- `install_mod.py` validates before copying only `42/` and `common/`, excluding `AGENTS.md`. It stages and hashes copies, refuses unowned destinations, requires `--update` for an owned install and keeps the prior package under the destination's grandparent `Javelin73PC-backups/` directory.
- Installation ownership is recorded in `.j73-install.json`; do not adopt another mod or an unmarked existing directory.
- `check_game_syntax.py` compiles `GameSyntaxCheck.java` in a temporary directory, using the installed game jar's Kahlua compiler and script parser without executing mod Lua or loading game worlds. Requires a JDK supporting release 25 and the game's bundled Java runtime.
- `InspectFbx.java` imports FBX read-only through the installed game's `jassimp64.dll`, calls its native mesh-name resolver and mesh-transform builder, and reports resolved geometry bounds and animation names. It does not render or initialize a game world. Compile with `javac --release 25 -classpath <game>/projectzomboid.jar -d <temporary-directory> tools/InspectFbx.java`, then run the bundled Java with `--enable-native-access=ALL-UNNAMED -classpath <temporary-directory>;<game>/projectzomboid.jar InspectFbx <game> <fbx> <mesh-node>...`.
- `check_fbx_import.py` wraps the native probe with temporary compilation and fails on material mesh splits, unresolved manifest mesh nodes or unexpected/missing named clips. It also checks the animation FBX's clip set.
- `check_model_pose.py` launches Blender without rendering, reads the original generated source and evaluates deformed vertex centroids at closed/open frames. Hood/trunk must rise, doors must swing outward symmetrically, windows must follow doors and lower independently. It never saves source or changes a running game.
- `prepare_runtime_test.py` copies only this mod into a marked disposable cache beneath `build/`, enables it in that cache and adds a development-only Lua audit. It never launches the game, copies user settings, or modifies the production package. Its `J73 Original Car Visual Test` native debug scenario creates a disposable no-save world with no zombies, a protected player and one repaired, fuelled car with its key. `--editor` requests the native vehicle editor only after that scenario enters the world and spawns the car; main-menu editor calls lack an initialized in-game state. Runtime auditing does not verify driving or model appearance.
- Runtime cache preparation writes the native `mods/reset-mods-42_00.txt` migration marker before launch, so a fresh Build 42 cache preserves its explicit test mod list.
- The development audit runs at game boot and world start, so server mechanics callbacks deferred at boot are checked after world initialization.
- Optional `prepare_runtime_test.py --auto-start` adds a one-shot menu render callback to the isolated audit hook. It waits for the native debug scenario menu before launching the no-save visual scenario; ordinary preparation never auto-starts a world.
- Optional `--exercise` checks native attachment and exit for all four seats, then starts the repaired fuelled engine and stops it after checking. It restores the test player after the check. These checks do not verify walking to doors, timed entry animations or driving controls. The scenario sets noon for visual inspection.
- Optional `--drive` extends the native exercise with a 10 km/h regulator request, speed/displacement evidence and native braking; it never claims manual control or road-handling verification. Optional `--panel-cycle` holds closed, open and lowered-window-with-open-door poses for twenty seconds each, then restores closed. Pose tags require visual inspection and are not automatic visual passes. The cycle accumulates only bounded active-tick time, so suspending world ticks in the vehicle editor cannot skip unseen poses. A combined gameplay suite waits for successful cycle completion as well as its nominal delay. Pose failure blocks the suite. `test_runtime_pose.py` executes the actual extracted scheduler with a fake clock/parts in the shipped Kahlua VM, including a three-minute pause and suite gating, without loading a game world. `RuntimePoseClockCheck.java` is its test-only runner.
- Optional `--gameplay` copies `runtime_gameplay.lua` as `J73GameplayAudit.lua` only into the disposable cache. It checks the native menu's pathfinding/door/timed seat entry and exit for four seats, seven native removal/install callback and repair paths, and headlight activation/deactivation. Mechanics callbacks do not prove the inventory/skill UI. Light state checks require separate beam/texture inspection.
- Optional `--save-test` enables saving only in the marked disposable cache and implies the gameplay suite. It uses native `save(true)` for a tagged vehicle, fuel, condition, window open state and trunk loot. Native windows persist their boolean state, not fractional opening positions. `Lua/j73-persistence-test.txt` records the exact test Sandbox world. Ordinary preparations remain no-save; never copy or target user saves.
