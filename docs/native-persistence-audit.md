## Shipped primary evidence

- `media/lua/client/OptionScreens/MainScreen.lua:1400`: native SOLO copies `ActiveMods.getById("default")` into `currentGame` before creating a new game.
- `media/lua/client/DebugUIs/DebugScenarios.lua`, `DebugScenarios:launchScenario`: calls the selected scenario's setSandbox, then createWorld and LoadingQueueState. It bypasses the SOLO copy.
- Installed `GameLoadingState.exit` bytecode251..293: in the nonclient path, obtains currentGame, checks missing mods/maps, calls setLoadedMods and writes the current save's `mods.txt` through ActiveModsFile. The writer returns without writing when NoSave is true; the explicit save-test scenario enables saving before this route.
- `ActiveMods.copyFrom` bytecode clears and copies both mods and mapOrder. `requiresResetLua` compares the loaded ordered mod list with the requested list. Neither method treats an empty list as a request for defaults.
- `LuaManager$GlobalObject.getSaveInfo` reads a valid saved ActiveModsFile into an ActiveMods object and supplies it as activeMods even when empty. `MainScreen.continueLatestSaveAux` copies that object into currentGame at1202; the fallback to default applies when the file is absent, not when it is valid and empty. At1233 it requests ResetLua("currentGame", "continueSave") if the requested and loaded selections differ.
- ActiveModsFile uses native VERSION=1 with mods/mod and maps/map blocks. The preserved failed42-byte file is valid native empty format, not a parser failure.

This explains why correct default.txt did not repair the reload. The next process initially loaded its default mods, but Continue switched to the saved empty set. `BaseVehicle.setScript(String)` also shows a missing named script invokes chooseRandomScript, then replaces runtime scriptName with the chosen script's full name. This supports the observed fallback vehicle; it does not establish which fields were subsequently persisted. Normal exit may have saved the fallback state, so editing mods.txt after that is not a reliable restoration proof. Parent chose a fresh disposable world and preserved the failure evidence.

## Valid world reload exposed a Set enumeration bug

The next native repeat retained both PZToolkitBridge and Javelin73PC in world86132284163120964967's mods.txt, and parent observed the actual Javelin after reload. This supports the active-mod initialization fix. Reload verification then stopped with `Object tried to call nil` at the helper's indexed vehicle enumeration. Parent preserved the console and screenshot under `build/parity-cycle8/native/`; this investigation did not modify that world or its profile.

Installed `IsoCell.getVehicles()` returns `java.util.Set<BaseVehicle>` and simply returns its vehicles field. Constructor bytecode300..307 initializes that field as HashSet. It has size/iterator methods but no indexed get(int). The Lua debugger's collection display does not establish a Lua array. The game Exposer explicitly registers HashSet and Iterator; the shipped ISVehicleBloodUI Lua still contains an indexed-list example, so that stale example must not override the actual Java type/exposure evidence.

The minimal fix changes only `verifyReload` enumeration in `tools/runtime_gameplay.lua`: obtain `vehicles:iterator()`, loop while `iterator:hasNext()` and retrieve `iterator:next()`. Existing `car:getModData()` and persistence assertions remain unchanged. No production vehicle callback changed.

`tools/test_runtime_vehicle_set.py` runs the actual extracted verifyReload function in the shipped Kahlua VM with the game's actual Exposer, real Java HashSet/Iterator and a real ArrayList for cargo. Car/part state is mocked, so this is an exact collection-interface regression rather than a native vehicle-instantiation test. It verifies an empty set waits, an unrelated vehicle is skipped, and the tagged car reaches all existing script/fuel/condition/window/loot checks. Before the patch, `enumerator-red-v03.log` reproduces the same RELOAD_FAIL nil-call through actual HashSet exposure. With the iterator patch, `enumerator-green-v01.log` passes. Earlier V01/V02 fixture setup failures are not the red behavioral proof.

The complete runtime hook also passes syntax-only compilation in `enumerator-syntax-v01.log`; the full unit run is `all-unit-enumerator-v01.log`. Parent retains the valid saved world and owns staged-hook replacement, PC verification and native replay. The successful collection regression does not itself claim a complete native save/reload pass.
